# 语音对话集成

Chat 通过外部小智 AI 服务完成一次手动启动的语音交流，需要 Wi-Fi，
并在 [xiaozhi.me](https://xiaozhi.me/) 注册账号、绑定设备。
不启用唤醒词、持续监听或自动循环对话。本指南介绍协议与资源边界，无需了解角色的游戏设定。

## 按键

| 状态 | 操作 | 结果 |
| --- | --- | --- |
| 选中 Chat 或未开启 | OK | 连接就绪后录音 |
| 录音 | OK | 结束录音，等待回复 |
| 连接、绑定、等待或播放 | OK | 取消当前交流 |
| 对话活动中 | 长按 OK | 停止对话 |
| 关闭或错误 | 长按 OK | 打开本地文字历史 |
| Chat 卡片 | UP / DOWN | 返回导航并停止对话 |
| 历史 | UP / DOWN | 每次滚动一行 |
| 历史 | OK／长按 DOWN | 跳至最新条目 |
| 历史 | 长按 OK | 返回未开启的 Chat |

麦克风仅在主动开启且通道就绪后运行。录音和回复播放分别限时两分钟。
专注完成会停止 Chat，让提示音播放。息屏后的首次按键只唤醒屏幕。

## 传输与任务职责

配置从 `https://api.tenclass.net/xiaozhi/ota/` 获取。
集成在 ESP-IDF 5.5.3 上实现激活 v1、MQTT 会话控制、AES-CTR UDP 语音包及
60 毫秒 Opus 帧。配置发现不安装固件，不启用远程工具或自动固件更新。
协议参考为 [FoloToy 小智实现](https://github.com/FoloToy/folo-ai-passport-xiaozhi/tree/72da544d1b51678f5d88967adc299b3aec956946)，
保留的许可见[此处](../main/xiaozhi-reference.LICENSE)。

`chat_model` 管理状态转换，`chat_service` 管理 HTTPS／MQTT／UDP 与编解码对象。
网络回调只投递有界消息，不访问 LVGL。Chat 与其他音频共用互斥锁。
TLS 使用可信证书验证服务端；日志不记录凭据、激活码、设备身份或对话正文。
设备绑定身份保存在本地，传输凭据仅临时持有。

## 历史与隐私

独立 `chatlog` 分区使用 128 KB、32 个擦除扇区轮换保存最近 15 条文字，
每条最多 767 字节 UTF-8 正文和一个结束符。语音识别与回复分句分别占用条目，
因此并非 15 轮完整对话。长内容在 UTF-8 字符边界截断，或使用多个条目。

记录包含序号、长度、校验和与最后写入的提交标记。未完成或损坏的写入不加载；
新写入不会擦除当前有效历史。完整文字会及时保存，传输中或未写完的内容仍可能丢失。
存储失败时退回最多 12 条 RAM 历史，不能保证重启恢复。
普通兼容的主程序更新可保留历史；完整擦除或不兼容镜像可能删除历史。

历史从映射 Flash 读取，仅渲染可见文字。16 像素字体覆盖常用汉字、标点与假名；
emoji、扩展汉字仍需额外字形。参见[字体许可](../assets/fonts/stelle-chat/LICENSE.txt)。
语音与识别文字会发送至配置的外部服务，本地历史保存在设备上。
不要公开设备凭据或真实聊天记录。

## 内存与连接复用

ESP32-C3 无 PSRAM。Chat 在 Wi-Fi／TLS 启动前预留 25 KB 编解码池；
编码器和解码器按阶段交替运行，复用同一区域。
集成只接管固定版本音频库在 Chat 任务中的分配；失败时不回退到碎片堆，
其他任务继续使用原分配器。任务栈为 27 KB。

一轮成功后，在 Chat／历史页前台最多保留 Wi-Fi 与 MQTT 连接 120 秒。
轮次之间关闭 UDP 语音通道，下次使用新的会话参数。
离开 Chat、息屏、闲置到期或传输错误会释放连接及临时凭据。
热连接失败时自动尝试一次完整连接。预留编解码对象不会启动麦克风。

## 验证

主机测试覆盖状态转换、包边界、排序、UTF-8 排版、连接复用、编解码池隔离和
断电存储恢复。设备上仍须验证绑定、收音、连续播放、编解码实际内存峰值、长回复与
连续交流。构建成功和原生预览不能证明这些硬件结果。
